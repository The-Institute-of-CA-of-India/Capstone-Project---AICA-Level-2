## Lessons learned

1. **A written spec plus phase gates kept the AI on track.** SPEC.md and CLAUDE.md were read at the start of every session; each phase ended with tests, a log entry and a review, and review findings became numbered change requests (CR-001 to CR-009) instead of silent drift.
2. **Deterministic law, advisory AI.** Keeping limitation, fees, tax effect and decisions in Python + YAML made every figure testable against expected values (e.g. S2: ₹37,11,344 / ₹3,02,016) and let the AI be switched off without loss.
3. **Verification is what makes extraction trustworthy.** Verbatim snippets with page / para, checked by `verify.py`, caught wrong references and stopped non-verbatim AI extracts.
4. **Synthetic samples prove the plumbing, not real-world accuracy.** Every synthetic order scored 100%; the one real NFAC order did not (DF-001). Real layouts need real (masked) diagnostics, so `diagnose_pdf.py` prints structure only and never the order's text.
5. **Local LLMs are usable but slow on a laptop.** gemma-3-12b-it needed 60–110 s per note and sometimes erred (s. 40(a)(ia) read as cash payments); short briefs, a section glossary and output validation fixed most of it. Notes are on demand and labelled.
6. **Check the app, not only the tests.** Browser checks found issues unit tests could not: tab jumps, cut dialog labels, COM initialisation for docx2pdf in a worker thread, table overflow at 1366 px.
7. **Ask before inventing law.** Every legal value not in the spec went into YAML as `verified: false` for the CA to confirm; 42 entries remain flagged in the app and report.
