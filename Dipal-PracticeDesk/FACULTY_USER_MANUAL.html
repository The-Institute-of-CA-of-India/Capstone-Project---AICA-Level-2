1. Start in three steps

  1. Extract the supplied ZIP and open the Dipal-PracticeDesk folder. Double-click START.html. It opens the hosted app. You do not need to copy code, install Apps Script or deploy a project.
  2. Sign in using your own Google account. Review Google’s requested permissions for account email identity, Sheets access and sending email. Do not enter a password into PracticeDesk; authentication is handled by Google.
  3. Wait for automatic database setup. The updated app creates or reconnects your personal Google Sheet, then opens the dashboard. Check that your email is shown in the header. Account provides the database link and connection checks.
Recommended first-run environment: use a fresh Chrome Incognito window, sign in to only one Google account and open the original app link. Separate Chrome profiles can still contain multiple website logins. A private session reduces account-selection conflicts.

Direct app link:
https://script.google.com/macros/s/AKfycbxjD5ORkffzmQ92GhTaMXSDEktt-qFmWyF8YPw-yskHHLfIP6ncvc4FT0J_dYa1FD8G/exec

If the automatic setup screen is missing, use Account → Connect / check account → Create my Google Sheets database. If those controls are unavailable, contact the owner to verify the deployed revision. START.html launches the existing deployment; it does not install a newer version of the app.

Sign-in, permissions and any Google OAuth/organization eligibility cannot be automated or bypassed. The owner must publish the included auto-setup update once. Faculty never need the creator’s login.

2. First five-minute walkthrough

  1. Confirm the account. Open Account and confirm your email and personal Sheet link. Run connection checks. This action does not send email.
  2. Add a fictional client. Choose Clients → Add client. For a real self-test, use an email address you control; do not email the supplied example.com sample contacts.
  3. Create an assignment. Choose New assignment, select the client, enter an assignment title, period, team owner and internal collection date. Choose an editable starter checklist or Custom.
  4. Tailor the requirements. Add/edit document names, notes and dates. Mark irrelevant items Not applicable and optional items as not required.
  5. Record partial receipt. Set one requirement to Partially received and explain what is still missing in its notes. Review the dashboard’s pending and overdue counts.
  6. Distinguish receipt from review. Received means the document arrived. Reviewed means the team has reviewed it. Update each deliberately.
  7. Prepare a reminder. Use Draft reminder to review/copy/download text without sending, or Send email for an explicitly confirmed submission.
  8. Record follow-up. Log actual contact through Log contact, enter the channel/outcome and set the next date. The Follow-ups desk prioritizes outstanding assignments.
  9. Wait for Saved. Refresh/reopen the app to confirm persistence. Export a JSON backup before ending the demonstration.

Use Explore demo for fictional built-in data. Demo is separate from your live records and cannot send email or save to the live database. Exit demo before actual integration tests.

3. Clients, imports and data

For bulk import, use Clients → CSV template, fill the four columns client_name, contact_person, email and phone, then save as CSV UTF-8. Import clients displays new, duplicate and invalid rows before confirmation. Only valid new rows are imported; existing records are not overwritten.

The supplied sample_data folder contains fictional examples and expected results. Its sample addresses are not test destinations. Keep phone numbers as text in Excel to retain leading zeros.

Google Sheets is the database. Make changes through PracticeDesk: Clients, Assignments, Documents, Contacts and Activity are generated readable views. Directly editing these views does not update the authoritative app records. Do not change or delete _Meta or _Snapshots. EmailLog contains submission attempts.

Each authorized Google user has a separate database. This release is not a shared-team database. Keep your Sheet private, and do not place real client information in a public project repository.

4. Test and send email safely

First test: send only to yourself

  1. Exit demo, then choose Account → Test email to myself.
  2. Confirm the displayed sending account and your own recipient address.
  3. Review subject/body, tick the authorization checkbox and choose Send email once.
  4. Wait for the result and inspect Email log. Do not resubmit while the result is unresolved.
  5. Independently find the message in your own Inbox or Spam folder. A UI status is not proof of delivery.

Assignment reminders

Open the assignment → Send email. Review the client’s recipient address, subject and pending-document list. Confirm the send explicitly. The sender is your authorized Google account; arbitrary From-address changes are not supported. Generating/downloading a draft is not sending it.

Displayed stateExact meaning
SendingA request was reserved before submission. The outcome is not yet confirmed.
Sent (accepted)Google’s sending call returned successfully. Delivery/read status is not established.
UnknownSubmission outcome could not be confirmed. Check before creating another request.
No automatic delivery/read/reply detection. The app does not inspect a recipient’s mailbox or detect incoming client replies. Do not mark document requirements Received merely because an email was sent.

Same-ID requests are not resent. Identical content submitted under a new ID is blocked for ten minutes. Email is never automatically retried. If Sending/Unknown persists, check the recipient/account and contact the owner.

5. Status, dates and synchronization

RuleMeaning
OutstandingRequired items with Pending or Partially received status.
OverdueAn outstanding item with an effective internal collection date before today.
Effective dateDocument-specific date, otherwise the assignment date. No date means not overdue.
Ready for reviewApplicable required items have arrived, with at least one still Received.
Checklist completeApplicable required items have been reviewed. This is not completion of the professional engagement.
No requirementsNo applicable required items remain. Optional and Not applicable items are excluded.

Dates are internal targets, not statutory compliance deadlines. Document receipt/review is entered by staff.

Changes are saved asynchronously to Google Sheets. Wait for Saved before closing. Open pages poll every 15 seconds while idle; polling pauses during dialogs, saves, edits and email submission. The app does not run background reminders while closed.

6. Troubleshooting — including known first-run issues

Try the least disruptive step first. Retain unsaved data and report the exact message. Do not delete your database or reinstall the project as a general troubleshooting step.

Google Drive: “Sorry, unable to open the file at present” / “Page not found”

What it may mean: The Google access page is failing before PracticeDesk opens. Multiple signed-in accounts, an unavailable deployment or access settings are possible causes. A URL containing /u/2/ alone does not establish the cause.

Faculty action: Close all existing Incognito windows. Open a fresh one with Ctrl+Shift+N. Paste the original /exec link and sign in using only one Google account. If it still fails, send the screenshot to the owner.

Important / owner action: Owner must verify that the deployment is active, the URL is current, it executes as the accessing user and access includes the intended signed-in users. Do not change application code based only on this message.

Google permission prompt / authorization required

What it may mean: Google requires the current user to authorize access to their Sheets, email sending and account email identity.

Faculty action: Review the named app and requested permissions. Approve only if you are satisfied that this is the intended project. If a required permission was omitted, ask the owner for the appropriate reauthorization process.

Important / owner action: Authorization is a user action. The launcher cannot approve permissions or enter a password for you.

“Google hasn’t verified this app” / “Access blocked” / assessor not eligible

What it may mean: OAuth verification, a testing-user restriction or an organization policy may apply.

Faculty action: Do not assume that the app can be used under this account. Share the exact message with the owner and request access resolution before continuing.

Important / owner action: Owner must resolve OAuth testing-user eligibility, verification or organization policy as applicable. Do not disable browser or organization security controls.

Not connected / Sending account: Not connected / Database: Not created

What it may mean: Startup has not finished, permission is missing, or an older interface is deployed.

Faculty action: Wait for the connection result. Open Account → Connect / check account. If offered, use Create my Google Sheets database. Creation does not send email and reuses the current user’s existing app database.

Important / owner action: If the startup/setup controls are missing, the owner must update Index.html and publish a new version of the existing deployment.

“SETUP: Create your personal database first”

What it may mean: A database-dependent action was requested before setup completed.

Faculty action: Complete the Account connection/database step before running checks or sending email. The updated app normally creates the database automatically after authorization.

Important / owner action: Repeated SETUP errors require the owner to inspect the deployed revision and database connection. Faculty should not create or edit database system tabs manually.

Connection checks show email permission unavailable

What it may mean: The app cannot currently obtain the sending permission or quota information.

Faculty action: Ask the owner to help resolve the Google authorization. Do not send client messages until permission checks pass.

Important / owner action: The app needs mail-sending permission, not access to read the Gmail inbox. A valid remaining quota may still change between executions.

Old screen appears / no automatic setup / recent fixes missing

What it may mean: The deployed /exec version may still contain earlier code, or the wrong link is being used.

Faculty action: Reopen the supplied original /exec link. If the old screen remains, contact the owner.

Important / owner action: Owner: Save the correct source, then Deploy → Manage deployments → Edit → New version → Deploy. Saving source alone does not update the existing deployed version. Keep the same URL or issue an updated launcher.

Apps Script “ParseError: Unexpected token =” at Code.gs line 23

What it may mean: An older server file used logical assignment syntax rejected by Apps Script. This is an owner/editor issue.

Faculty action: Report the complete error to the owner. Faculty do not need to edit or install server code.

Important / owner action: Owner: use the corrected Code.gs from this package. It replaces the two nullish assignments with explicit null/undefined checks. Save and update the deployment. Do not restore old code from an earlier ZIP.

Saving… / Save blocked / connection timeout

What it may mean: Changes have not yet been confirmed in Google Sheets. A lost response does not necessarily mean the save failed.

Faculty action: Keep the tab open and export a JSON backup before leaving. Account → Retry save uses the existing save request ID. Wait for Saved.

Important / owner action: Do not clear browser data, close the tab or repeatedly restore a backup while unsaved changes remain. Sending is blocked until saves are resolved.

“CONFLICT: Another tab saved newer data”

What it may mean: A different tab saved a later revision. The stale update was rejected to prevent overwriting it.

Faculty action: Export a local backup of your changes. Close unnecessary tabs. Reload the current Sheet version through Account after confirming that you have retained your local changes.

Important / owner action: Reconcile the two versions deliberately. Restoring an old backup over the new version without review can discard newer records.

Email stays “Sending” or becomes “Unknown”

What it may mean: The app cannot confirm the final submission outcome. The email might already have been submitted.

Faculty action: Refresh Email log and independently check with the intended recipient. For a self-test, check your own Inbox/Spam. Contact the owner if the result remains unresolved.

Important / owner action: Do not repeatedly press Send or create another request without checking: that can cause a duplicate. PracticeDesk does not automatically retry email.

“DUPLICATE” or request-ID warning

What it may mean: The same request was already processed, or an identical message was submitted recently.

Faculty action: Inspect Email log first. Reusing a request ID does not send again; identical content under a new ID is blocked for ten minutes.

Important / owner action: Do not change text solely to bypass the duplicate guard. Confirm whether the first message was submitted before considering another send.

Email says “Sent (accepted)” but the recipient cannot find it

What it may mean: Google accepted the sending call; this is not proof of inbox delivery or reading.

Faculty action: Confirm the recipient address. For your self-test, inspect Inbox and Spam. Allow time for mail processing and ask the intended recipient to check.

Important / owner action: Delivery, bounce, read status and incoming client replies are not automatically tracked. Do not mark document requirements Received solely because an email was accepted.

“QUOTA” / no daily recipients remaining

What it may mean: Google reports that the account has no remaining email-recipient quota at that moment.

Faculty action: Do not repeatedly resend. Wait for quota availability and run the check again, or discuss an approved alternative with the owner.

Important / owner action: The application does not control Google’s quotas or their reset timing.

CSV rejected / duplicate client / invalid email

What it may mean: The template structure or a row value does not pass validation.

Faculty action: Use the Clients → CSV template headers: client_name, contact_person, email, phone. Save as CSV UTF-8. Review the preview/import report. Duplicate names are matched after normalizing spaces and case.

Important / owner action: Only new valid rows are imported after confirmation. Existing client details are not overwritten. Keep phone numbers as text in Excel to preserve leading zeros.

A document is missing from the reminder or pending count

What it may mean: The item may be Received, Reviewed, Not applicable or optional.

Faculty action: Review its status and Required checkbox. Required Pending and Partially received items count as outstanding. Optional items can be included in a reminder through its optional-items control.

Important / owner action: Checklist completion concerns requirements only; it is not completion of the audit, return or professional engagement.

“DATABASE”, “OWNER” or “INTEGRITY” error

What it may mean: The Sheet may be inaccessible, the identity may not match, or system data may have been altered.

Faculty action: Stop editing and sending. Retain any local backup and report the exact error to the owner.

Important / owner action: Do not delete the Sheet, change _Meta/_Snapshots, share account credentials or attempt to bypass ownership checks. Owner should restore access or a verified backup through the supported process.

Demo changes disappear / email unavailable in demo

What it may mean: Demo mode is intentionally separate from the live workspace.

Faculty action: Exit demo to return to your own records. Use Account → Test email to myself outside demo for an actual test.

Important / owner action: Demo mode does not send email or write changes to the live Sheet.

7. Backups and ending the session

  1. Wait until changes show Saved.
  2. Use Backup to download a JSON file containing the workspace. Store it in an appropriate private location.
  3. Use CSV exports for the document register and contact history where needed.
  4. Restore only when you intend to replace the current workspace. Export its current state first. A JSON restore is not a merge.
  5. Close the app. Shared-computer users should also end their Google/private browsing session appropriately.

Avoid collecting unnecessary identifiers in notes. Editable Sheet logs are operational records, not tamper-proof audit evidence.

8. What to send the owner if blocked

  • A screenshot of the exact error, with unrelated personal/client information redacted.
  • Whether the original /exec link or START.html was used.
  • Whether the test used a fresh single-account private window.
  • The approximate time and the last action performed.
  • For email: the request ID and displayed status from Email log.

Never send a password, access token, recovery code or full client database. The owner may request deployment settings or Google authorization diagnostics; faculty do not need to modify server code.

Verification record

The owner reported the app was working during preparation. The package includes 44 simulated checks. Those do not independently establish email delivery or second-account acceptance. Actual deployment revision, Google permissions and self-test email receipt must be verified in the user's session.
