# Five-minute demonstration

Use only fictional data. Complete deployment and the live acceptance checklist before presenting.

| Time | Demonstration |
| --- | --- |
| 0:00–0:40 | Explain the CA document-follow-up problem and show the current signed-in account. |
| 0:40–1:20 | Add a fictional client and create an audit assignment; point out the period, owner and collection target. |
| 1:20–2:00 | Mark one item Partially received and enter what remains missing; show the pending/overdue counts. |
| 2:00–2:50 | Review a reminder. Explain that Received/Reviewed items are excluded and no email is sent without explicit confirmation. |
| 2:50–3:30 | If live testing passed, submit a self-addressed test and inspect Email log. Independently verify mailbox receipt. Otherwise disclose that the integration is not live-verified and demonstrate the draft only. |
| 3:30–4:10 | Log actual/fictional demonstration contact, schedule the next follow-up and open the follow-up desk. |
| 4:10–4:40 | Open the Google Sheet and reload the app to show persistence. |
| 4:40–5:00 | Explain account isolation, export a backup and state limitations. |

## Questions

**Does Sent mean delivered?** No. It means the send call was accepted. Delivery/read/reply detection is not implemented.

**Is this a live AI agent?** No. AI assisted development. The runtime uses deterministic rules and reminder templates.

**Does complete mean audit complete?** No. It refers only to the applicable checklist requirements.

**Can assessors use their own login?** The accessing-user design supports separate accounts and separately created Sheets, subject to actual Google authorization and policy eligibility.
